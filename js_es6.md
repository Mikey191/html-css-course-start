## 🟠 1. Введение в ECMAScript

### 🔹 Что такое `ECMAScript` и как он связан с `JavaScript`

Для начала нужно чётко различать понятия:

- **JavaScript** — это полноценный язык программирования, который используется для создания логики в веб-браузерах, серверной части (через Node.js) и даже для создания десктопных или мобильных приложений.
- **ECMAScript (ES)** — это не сам язык, а стандарт, спецификация, описывающая, каким должен быть JavaScript.

Таким образом:

- `ECMAScript` — это не сам код, а документ, в котором указано, как должен вести себя JavaScript: какие есть типы данных, ключевые слова, как работают функции, классы, модули, какие есть структуры данных и т. д.
- `JavaScript` — это конкретная реализация этой спецификации в браузерах, Node.js и других платформах.

Например, движки V8 (Google), SpiderMonkey (Mozilla), JavaScriptCore (Apple) — это реализации ECMAScript в конкретных платформах.

---

### 🔹 Почему важны версии (`ES5`, `ES6 / ES2015`, `ES2024`…)

Язык JavaScript **эволюционирует** в соответствии со стандартом ECMAScript. Эта эволюция идёт в виде версий:

- **ES3** (1999 года) — считалась классической версией JavaScript, долгое время основой для всех браузеров.
- **ES5** (2009 года) — важный этап, который стандартизировал много аспектов JS для современных браузеров. Многие популярные фреймворки (например, jQuery) были из этой эпохи.
- **ES6 / ES2015** — ключевая веха в истории языка, крупный скачок в удобстве и функционале.
- **ES2016–ES2024** — ежегодный цикл обновления стандарта, в каждую версию приходят новые возможности.

Таким образом, каждое новое издание ECMAScript:

- Дополняет язык новыми удобствами.
- Закрывает старые проблемы.
- Дает разработчикам инструменты для создания чистого, удобного и современного кода.

---

### 🔹 Почему ES6 — ключевой стандарт

До ES6 в JavaScript приходилось бороться со множеством проблем:

- Отсутствие удобной области видимости для переменных (`var` имел функциональную область видимости).
- Отсутствие короткого, удобного синтаксиса для создания функций.
- Нет удобной записи для создания классов.
- Отсутствовали средства для удобной работы с коллекциями данных.

**ES6** (так же называемый ES2015) стал революцией в истории JavaScript:

- Добавил ключевые инструменты для создания современных приложений:

  - Ключевые слова `let` и `const` для объявления переменных с учётом блочной области видимости.
  - Стрелочные функции (`=>`).
  - Классы (`class`) как удобный синтаксис для создания объектов.
  - Деструктуризацию для удобного извлечения данных из массивов и объектов.
  - `Promise` для удобной асинхронной логики.
  - `import` и `export` для организации модулей.

- Закрыл множество проблем ранних версий JS, делая код коротким, удобным и предсказуемым.

Именно поэтому **ES6** считается важнейшим этапом развития языка. Его приход в 2015 году дал толчок огромной популярности современных фреймворков (React, Angular, Vue) и стал основой для всех следующих версий.

---

### 🔹 Какие возможности добавил ES6 и зачем их внедряли

#### Ключевые изменения в ES6:

1. **Объявления переменных:**

   - `let` и `const` — переменные с блочной областью видимости.
   - Уменьшение проблем с видимостью данных, коллизией имён.

2. **Стрелочные функции (`=>`):**

   - Короткая и удобная запись анонимных функций.
   - Упрощение работы с колбек-функциями, особенно в методах массива.

3. **Шаблонные строки:**

   - Удобный формат записи многострочных строк.
   - Простая подстановка данных в строки (`${name}`).

4. **Деструктуризация:**

   - Упрощение извлечения данных из массивов и объектов:

     ```js
     const [a, b] = [1, 2];
     const { name, age } = user;
     ```

5. **Параметры по умолчанию:**

   - Значения, автоматически подставляемые в аргументы, если они не были переданы:

     ```js
     function greet(name = 'Гость') { ... }
     ```

6. **Rest и Spread (`...`):**

   - Упрощение работы с массивами и объектами:

     - Сбор данных в массив (`...args`).
     - Расширение массивов или объектов (`[...arr]` или `{...obj}`).

7. **Цикл `for...of`:**

   - Удобный перебор элементов массивов и коллекций.

8. **Промисы (`Promise`):**

   - Явный механизм для удобной работы с асинхронностью.
   - Позволяют создавать цепочки операций и ловить ошибки.

9. **Модули (`import`/`export`):**

   - Явный механизм организации большого приложения в удобный, поддерживаемый код.

---

### 🔹 Итог: Зачем это нужно

- `ES6` — не просто несколько удобных фич, это принципиально **новый стандарт**, который закрыл множество проблем старого JavaScript.
- Его приход сделал язык удобным для создания крупных приложений, в которых код должен быть чистым, модульным, поддерживаемым.
- Сегодня весь современный JavaScript (включая React, Angular, Node.js) ориентируется именно на ES6+.

---

#### 👇 Ключевые тезисы:

✅ **ECMAScript** — стандарт, определяющий JavaScript.
✅ Каждый год выходят новые редакции стандарта (ES2015, ES2016, … ES2024).
✅ **ES6 (ES2015)** — ключевое обновление, изменившее сам стиль программирования в JavaScript.
✅ ES6 дал удобный синтаксис для переменных, функций, классов, работы с данными и модулями.
✅ Без понимания ES6 невозможно писать чистый и современный JavaScript.

## 🟠 2. Объявление переменных: `var`, `let`, `const`

---

### 🔹 `var` — устаревшее, функциональная область видимости

`var` — ключевое слово для объявления переменных в старом JavaScript (ES3, ES5).
Главная особенность: **`var` имеет функциональную область видимости**, а не блочную.
При использовании `var` в блоках (например, в `if` или в `for`), переменная доступна за пределами этих блоков.

#### Пример:

```javascript
if (true) {
  var oldVar = "Я видим даже за пределами if";
}
console.log(oldVar); // 'Я видим даже за пределами if'
```

> ⚠️ Это приводит к потенциальным проблемам, потому что кажется, что `oldVar` должен быть видим только в пределах `{}`, но это не так.

---

### 🔹 `let` и `const` — блочная область видимости

С приходом `ES6` были введены `let` и `const`.
Их особенность — видимы ТОЛЬКО в пределах блока `{ ... }`, в котором объявлены.

#### Примеры:

```javascript
if (true) {
  let blockVar = "Я видим только в пределах if";
}
console.log(blockVar); // ReferenceError: blockVar is not defined
```

```javascript
for (let i = 0; i < 3; i++) {
  console.log(i); // 0, 1, 2
}
console.log(i); // ReferenceError
```

---

### 🔹 Поведение в циклах, функциях и асинхронности

При рассмотрении различий между `var` и `let` в ES6 самое популярное и иллюстративное сравнение — это поведение в сочетании с асинхронным кодом, например в колбэке `setTimeout`.
Без `setTimeout` различия не видны, потому что весь код выполняется сразу же, в той же области видимости, где счётчик доступен.
Но как только появляется **асинхронный вызов**, становятся очевидны различия в области видимости.

#### 👉 Почему используется `setTimeout` для проверки?

`setTimeout()` выполняет переданную в него функцию не прямо сейчас, а **через определённый промежуток времени**. К моменту её вызова сам цикл уже завершится. Поэтому:

- При `var` используется одна и та же переменная `i` для всего цикла.
- При `let` — для каждой итерации создаётся собственный экземпляр `i`, который «запомнит» свою конкретную величину даже в асинхронной колбек-функции.

#### 🔹 С `var` в асинхронной ситуации:

```javascript
for (var i = 0; i < 3; i++) {
  setTimeout(() => {
    console.log(i);
  }, 100);
}
// Выведет: 3, 3, 3
```

**Причина:**
Цикл выполняется мгновенно, `i` в конце становится равной `3`. Так как в колбеке используется одна и та же переменная `i` (с функц. областью видимости), то во время выполнения `setTimeout` значение `i` уже будет `3`.

---

#### 🔹 С `let` в асинхронной ситуации:

```javascript
for (let i = 0; i < 3; i++) {
  setTimeout(() => {
    console.log(i);
  }, 100);
}
// Выведет: 0, 1, 2
```

**Причина:**
`let` имеет блочную область видимости. Для каждой итерации создаётся собственный экземпляр `i`. Когда вызываются колбек-функции из `setTimeout`, в каждой из них захвачено то значение `i`, которым эта конкретная итерация обладала в момент создания.

---

#### ✅ Итог: Зачем это нужно знать

В примерах подчёркивается ключевое различие в области видимости `var` и `let`, а также то, как это различие проявляется в асинхронном коде (через колбеки, обработчики событий и т. д.).

Без асинхронности различия не видны, потому что весь цикл выполняется в пределах одного стека вызова. Но как только появляется асинхронный вызов — различия становятся очевидны и важны для правильного понимания, как работают области видимости в JavaScript.

---

### 🔹 Когда использовать `const`, когда `let`

✅ **Используем `const`**:

- Для данных, которым не нужно переприсвоение:

  - Ссылок на массивы, объекты.
  - Значений, не изменяющихся в течение жизни программы.

Примеры:

```javascript
const pi = 3.1415926535;

const user = { name: "Иван" };
user.name = "Пётр"; // Допустимо, так как сам объект не переписываем, а лишь изменяем его свойства
```

✅ **Используем `let`**:

- Когда нужно изменить значение:

  - Счётчики в циклах.
  - Переменные для изменения данных в определённых блоках.

Примеры:

```javascript
let counter = 0;
counter = counter + 1;

let currentUser = "Иван";
currentUser = "Мария";
```

---

### 🔹 Hoisting (Поднятие) и потенциальные ошибки

#### Что нужно знать:

- `var` поднимается («hoisted») в начало области видимости и инициализируется значением `undefined`.
- `let` и `const` также поднимаются, но находятся в **зоне временной мёртвости (TDZ)** — доступ к ним запрещён, пока не выполнится объявление.

#### `var` — Hoisting:

```javascript
console.log(a); // undefined
var a = 10;
```

#### `let` / `const` — TDZ:

```javascript
console.log(b); // ReferenceError
let b = 20;

console.log(c); // ReferenceError
const c = 30;
```

---

### 🎯 Итоговые ключевые различия:

| Ключевое слово | Область видимости           | Допускает повторное объявление | Допускает переприсвоение | Поднятие (Hoisting) |
| -------------- | --------------------------- | ------------------------------ | ------------------------ | ------------------- |
| **var**        | Функциональная / Глобальная | ✅ (да)                        | ✅ (да)                  | ✅ (undefined)      |
| **let**        | Блочная                     | ❌ (нет)                       | ✅ (да)                  | ⚠️ TDZ              |
| **const**      | Блочная                     | ❌ (нет)                       | ❌ (нет)                 | ⚠️ TDZ              |

---

### 🔥 Памятка

- Когда не нужно менять значение — `const`.
- Когда нужно менять значение — `let`.
- `var` — не используется в современных приложениях, кроме случаев поддержки старого кода.

---

### ✅ Советы:

1. Для современных приложений забудьте про `var`.
2. Для неизменяемых данных используйте `const`.
3. Для изменяемых данных используйте `let`.
4. Старайтесь объявлять переменную максимально близко к месту её использования — это снижает вероятность ошибок.

---

### 👇 Итоговые короткие примеры для закрепления:

#### Три ключевых различия:


## 🟠 3. Стрелочные функции (`=>`)

---

### 🔹 Что это такое и почему это нужно

Стрелочные функции — это короткая и удобная альтернатива обычным функциональным выражениям в JavaScript. Они были введены в **ES6** для упрощения записи коротких колбек‑функций.

#### Ключевые особенности:

✅ Короткий синтаксис.
✅ Нет собственного `this`.
✅ Удобны для колбек‑функций (`map`, `filter`, `forEach` и т. д.).

---

### 🔹 Синтаксис: короткая форма записи

#### Обычная функция:

```javascript
const sum = function (a, b) {
  return a + b;
};
```

#### Стрелочная функция:

```javascript
const sum = (a, b) => a + b;
```

> 👉 Когда есть только один аргумент, скобки можно опустить:
> `const square = x => x * x;`

---

### 🔹 Отсутствие собственного `this`

Стрелочные функции не создают собственный `this`. Они автоматически захватывают значение `this` из окружения, в котором определены.

#### Ситуация 1 — Традиционная функция

```javascript
const person = {
  name: "Иван",
  sayHello: function () {
    console.log(this.name);
  },
};
person.sayHello(); // Иван
```

#### Ситуация 2 — Стрелочная в методе объекта

```javascript
const person = {
  name: "Иван",
  sayHello: () => {
    console.log(this.name);
  },
};
person.sayHello(); // undefined
```

> ⚡️ Почему? `this` в стрелочных функциях не связан с самим объектом — он ссылается на `this` из области видимости, в которой объявлена стрелочная функция.
> Поэтому в методах объекта стрелочную функцию использовать не стоит.

---

### 🔹 Когда НЕ стоит использовать стрелочную функцию

- Для создания методов объекта (см. выше).
- Для создания обработчиков, которым нужен собственный `this`.
- Для создания методов класса.

#### 👇 Пример ошибки

```javascript
const person = {
  name: "Мария",
  getName: () => {
    return this.name;
  },
};
console.log(person.getName()); // undefined
```

#### 👇 Правильно

```javascript
const person = {
  name: "Мария",
  getName() {
    return this.name;
  },
};
console.log(person.getName()); // 'Мария'
```

---

### 🔹 Где удобны стрелочные функции

Стрелочные функции идеальны для коротких колбеков:

- При обработке массивов (`map`, `filter`, `forEach`, `reduce`).
- Для обработчиков событий.
- Для создания коротких утилит.

#### 👇 Метод `map`

`map` — это метод массива, который:

- Проходит по каждому элементу массива.
- Вызывает колбек-функцию для каждого элемента.
- Формирует и возвращает НОВЫЙ массив из результатов.

**Без стрелочных функций:**

```javascript
const nums = [1, 2, 3];
const doubled = nums.map(function (num) {
  return num * 2;
});
console.log(doubled); // [2, 4, 6]
```

**Со стрелочными функциями:**

```javascript
const nums = [1, 2, 3];
const doubled = nums.map((num) => num * 2);
console.log(doubled); // [2, 4, 6]
```

> 👆 Код короче, удобнее и проще для чтения.

#### 👇 Метод `filter`

```javascript
const nums = [1, 2, 3, 4, 5];
const even = nums.filter((n) => n % 2 === 0);
console.log(even); // [2, 4]
```

#### 👇 Метод `forEach`

```javascript
const nums = [1, 2, 3];
nums.forEach((n) => console.log(n * 10));
// Выведет:
// 10
// 20
// 30
```

---

### 🔹 Дополнительно: Явный и неявный `return`

- Для коротких колбек‑функций в одну строку используется **неявный return**:

```javascript
const multiply = (a, b) => a * b;
```

- Для многострочных используется фигурная скобка и явный `return`:

```javascript
const multiply = (a, b) => {
  const result = a * b;
  return result;
};
```

---

### ✅ Итоговые ключевые моменты:

- Стрелочные функции коротки и удобны для колбеков и массивов.
- У них нет собственного `this` — он наследуется из внешней области видимости.
- Не подходят для создания методов объекта или класса.
- Идеально подходят для коротких операций, обработчиков массива (`map`, `filter`, `forEach` и т. д.).

---

### 👇 Дополнительно: Сводный список различий

| Критерий                      | Традиционная функция     | Стрелочная функция            |
| ----------------------------- | ------------------------ | ----------------------------- |
| Синтаксис                     | `function(a, b) { ... }` | `(a, b) => ...`               |
| Имеет собственный `this`      | ✅                       | ❌ (берёт из внешней области) |
| Идеально для методов объекта  | ✅                       | ❌                            |
| Короткая запись               | Нет                      | ✅                            |
| Подходит для колбеков массива | ✅                       | ✅ (предпочтительнее)         |

---

### 👇 Дополнительно для понимания (полный короткий пример):

```javascript
// Традиционный колбек
[1, 2, 3].forEach(function (num) {
  console.log(num);
});

// Тот же код со стрелочной функцией
[1, 2, 3].forEach((num) => console.log(num));

// Метод массива .map()
const doubled = [1, 2, 3].map((num) => num * 2);
console.log(doubled);

// Метод массива .filter()
const even = [1, 2, 3, 4].filter((num) => num % 2 === 0);
console.log(even);

// Метод массива .reduce()
const total = [1, 2, 3, 4].reduce((sum, num) => sum + num, 0);
console.log(total);
```

---

**Итог:**
Стрелочные функции — важный инструмент для современных JavaScript‑разработчиков. Они позволяют писать короткий, чистый, удобный код для колбеков и операций над массивами, но не подходят для создания методов объектов, которым нужно собственное значение `this`.

## 🟠 4. Аргументы по умолчанию

---

### 🔹 Зачем нужны аргументы по умолчанию

Частая ситуация:
При вызове функции не всегда приходят все аргументы.
Для таких случаев в **ES6** были введены **значения параметров по умолчанию** — удобный механизм, позволяющий:

✅ Избавиться от проверки типа `if (param === undefined) {...}`
✅ Сразу указать значение прямо в определении функции.

---

### 🔹 Синтаксис

```javascript
function greet(name = "Гость") {
  console.log(`Привет, ${name}!`);
}
```

#### 👇 Примеры вызова:

```javascript
greet("Иван"); // Выведет: "Привет, Иван!"
greet(); // Выведет: "Привет, Гость!"
```

---

### 🔹 Значение используется ТОЛЬКО для `undefined`

Важно понимать:
**Значение по умолчанию используется ТОЛЬКО если аргумент равен `undefined`.**
Для других значений (включая `null`, `0`, `''`, `false`) дефолт НЕ применяется.

#### 👇 Показываем различия:

```javascript
function test(value = "По умолчанию") {
  console.log(value);
}

test("Привет"); // 'Привет'
test(); // 'По умолчанию' (так как value === undefined)
test(undefined); // 'По умолчанию' (так как value === undefined)
test(null); // null (так как value не undefined!)
test(""); // '' (так как value не undefined!)
test(false); // false
test(0); // 0
```

---

### 🔹 Допустимы любые выражения в качестве дефолтного значения

Значение по умолчанию может быть:

- Простыми литералами
- Выражением
- Значением, полученным из другой функции

#### 👇 Простое значение

```javascript
function hello(greeting = "Привет") {
  console.log(greeting);
}
hello(); // 'Привет'
hello("Добрый день"); // 'Добрый день'
```

#### 👇 Выражение

```javascript
function multiply(a, b = a * 2) {
  return a * b;
}
console.log(multiply(5)); // 25 (так как b = 5 * 2 = 10, результат 5 * 10)
```

#### 👇 Значение из другой функции

```javascript
function getDefaultName() {
  return "Неизвестный";
}

function sayHello(name = getDefaultName()) {
  console.log(`Привет, ${name}!`);
}

sayHello("Иван"); // 'Привет, Иван!'
sayHello(); // 'Привет, Неизвестный!'
```

---

### 🔹 Зачем это нужно в реальной практике

#### 1️⃣ Убираем проверки в начале функции

Без дефолтных значений:

```javascript
function connect(server, port) {
  server = server || "localhost";
  port = port || 80;

  console.log(`Соединение с ${server}:${port}`);
}
```

С дефолтами:

```javascript
function connect(server = "localhost", port = 80) {
  console.log(`Соединение с ${server}:${port}`);
}
```

#### 2️⃣ Явный контракт

При чтении объявления:

```javascript
function createUser(name = 'Гость', isAdmin = false) { ... }
```

Сразу ясно, какие значения будут использоваться, даже если не передать аргументы.

---

### 🔹 Значения по умолчанию в сочетании с деструктуризацией

Используем дефолтное значение для объекта в качестве параметра:

```javascript
function createUser({ name = "Гость", role = "user" } = {}) {
  console.log(`Имя: ${name}, Роль: ${role}`);
}

createUser({ name: "Иван" });
// Имя: Иван, Роль: user

createUser();
// Имя: Гость, Роль: user
```

Таким образом:
✅ Значения по умолчанию упрощают обработку даже сложных случаев.
✅ Избавляют от проверки наличия объекта или отдельных свойств.

---

### 🔥 Итоговые ключевые моменты

- Значение по умолчанию используется ТОЛЬКО для `undefined`.
- Синтаксис прост: `function fn(param = value)`.
- Значение может быть результатом вызова другой функции.
- Убирают большое количество проверок в начале функции.
- Позволяют чётко документировать контракт для ваших пользователей.

---

### 👇 Дополнительно: Сводный короткий список различий

| Значение                   | Аргументы по умолчанию?     |
| -------------------------- | --------------------------- |
| Передан `undefined`        | ✅ Значение по умолчанию    |
| Не передан совсем          | ✅ Значение по умолчанию    |
| Передан `null`             | ❌ Значение не используется |
| Передан `0`, `false`, `''` | ❌ Значение не используется |

---

### 💡 Итог

**Аргументы по умолчанию** — удобный, короткий и современный механизм, который упрощает чтение и сопровождение кода. Они позволяют сделать функции самодостаточными и предсказуемыми даже в случае отсутствия части данных.

## 🟠 5. Деструктуризация объектов и массивов

---

### 🔹 Что это и зачем нужно

**Деструктуризация** — удобный механизм в JavaScript для извлечения данных из объекта или массива прямо в момент создания переменных.
Без деструктуризации приходилось писать много повторяющегося кода:

```javascript
const user = {
  name: "Иван",
  age: 25,
};
const name = user.name;
const age = user.age;

console.log(name, age);
```

С помощью деструктуризации это делается коротко и прямо в момент объявления:

```javascript
const user = {
  name: "Иван",
  age: 25,
};
const { name, age } = user;

console.log(name, age); // Иван 25
```

---

### 🔹 Деструктуризация объекта

#### 👇 Простая форма:

```javascript
const user = {
  name: "Иван",
  age: 25,
};
const { name, age } = user;

console.log(name); // Иван
console.log(age); // 25
```

#### 👇 Смена имён переменных:

```javascript
const user = {
  name: "Иван",
  age: 25,
};
const { name: userName, age: userAge } = user;

console.log(userName); // Иван
console.log(userAge); // 25
```

#### 👇 Значение по умолчанию:

```javascript
const user = {
  name: "Иван",
};
const { name, age = 18 } = user;

console.log(name); // Иван
console.log(age); // 18 (так как в объекте нет свойства age)
```

---

### 🔹 Деструктуризация прямо в параметрах функции

Позволяет сделать код удобнее — достать данные прямо из объекта, приходящего в аргументы:

```javascript
function printUser({ name, age }) {
  console.log(`${name} — ${age}`);
}
printUser({ name: "Иван", age: 25 }); // Иван — 25
```

💡 **Как это работает?**
При вызове:

```javascript
printUser({ name: "Иван", age: 25 });
```

JavaScript видит, что в определении функции используется `{ name, age }`.
Таким образом:

- Из приходящего объекта автоматически извлекаются `name` и `age`.
- Переменные `name` и `age` создаются прямо в момент вызова.

---

#### 👇 Значение по умолчанию для параметров

Иногда вызова может не быть или приходящие данные не содержат нужных свойств.
Используем дефолтный объект и дефолтные значения для свойств:

```javascript
function printUser({ name = "Гость", age = 18 } = {}) {
  console.log(`${name} — ${age}`);
}
printUser({ name: "Мария" }); // Мария — 18
printUser(); // Гость — 18
```

💡 **Как это работает?**

1. `{ name = 'Гость', age = 18 }` — дефолт для свойств.
2. `= {}` — дефолтный объект для самого аргумента (чтобы вызов `printUser()` не вызывал ошибки).

---

### 🔹 Деструктуризация массива

#### 👇 Простая форма:

```javascript
const colors = ["red", "green", "blue"];

const [first, second, third] = colors;

console.log(first); // red
console.log(second); // green
console.log(third); // blue
```

#### 👇 Значение по умолчанию:

```javascript
const nums = [10];
const [a, b = 20] = nums;

console.log(a); // 10
console.log(b); // 20 (так как в массиве нет второго элемента)
```

#### 👇 Перескакивание элементов:

```javascript
const nums = [1, 2, 3];
const [first, , third] = nums;

console.log(first); // 1
console.log(third); // 3
```

#### 👇 Остаток элементов (Rest-оператор):

```javascript
const nums = [1, 2, 3, 4, 5];
const [first, second, ...other] = nums;

console.log(first); // 1
console.log(second); // 2
console.log(other); // [3, 4, 5]
```

---

### 🔹 Комбинирование объекта и массива

Иногда приходящие данные содержат несколько уровней вложенности. Например:

```javascript
const response = {
  status: "ok",
  data: {
    users: [{ name: "Иван" }, { name: "Мария" }, { name: "Пётр" }],
  },
};
```

Используем многоуровневую деструктуризацию:

```javascript
const {
  status,
  data: { users },
} = response;

const [firstUser, secondUser] = users;

console.log(status); // 'ok'
console.log(firstUser.name); // 'Иван'
console.log(secondUser.name); // 'Мария'
```

#### 👇 Схематично:

```
response
├─ status: 'ok'               ➔ status
└─ data
    └─ users: [user1, user2, user3] ➔ users
           ↓
           firstUser = user1
           secondUser = user2
```

💡 Так в начале видим, какие данные приходят из объекта, а потом работаем прямо с нужным уровнем, не повторяя обращения `response.data.users[...]`.

---

### ✅ Итоговые ключевые моменты

1. **Для объектов**:

   - Извлечение свойств в короткой записи: `const { name, age } = user`.
   - Изменение имён переменных.
   - Значения по умолчанию для отсутствующих свойств.

2. **Для массивов**:

   - Извлечение элементов массива в короткой записи.
   - Значения по умолчанию для отсутствующих элементов.
   - Перескакивание элементов.
   - Сбор остальных элементов (`...other`).

3. **Для комбинаций**:

   - Извлечение данных из сложной структуры прямо в момент объявления.
   - Упрощение чтения и понимания приходящих данных.

---

### 💡 Почему это удобно

- Убирает избыточный код обращения типа `user.name`.
- Явно документирует структуру данных прямо в начале.
- Удобно извлекать данные из приходящих данных API.
- Значительно облегчает чтение, сопровождение и обработку данных.

---

### 👇 Итоговые короткие примеры для запоминания

#### Из объекта:

```javascript
const person = { name: "Иван", age: 30 };
const { name, age } = person;
console.log(name, age);
```

#### Из массива:

```javascript
const nums = [1, 2, 3];
const [first, second] = nums;
console.log(first, second);
```

#### Значение по умолчанию:

```javascript
const [a, b = 10] = [1];
console.log(a, b); // 1, 10
```

#### Для параметров:

```javascript
function show({ name, age }) {
  console.log(`${name} — ${age}`);
}
show({ name: "Иван", age: 25 }); // Иван — 25
```

## 🟠 6. Spread и Rest операторы (`...`)

---

### 🔹 1️⃣ Rest — Сбор аргументов в массив

**Идея:** Когда вы не знаете заранее, сколько аргументов придёт в функцию, или хотите собрать все оставшиеся аргументы в массив.

#### 👇 Простая реализация

```javascript
function sum(...args) {
  console.log(args);
}

sum(1, 2, 3, 4, 5);
// Выведет: [1, 2, 3, 4, 5]
```

#### 👇 Суммирование всех аргументов

```javascript
function sum(...args) {
  return args.reduce((acc, num) => acc + num, 0);
}

console.log(sum(1, 2, 3)); // 6
console.log(sum(10, 20, 30, 40)); // 100
```

#### 👇 Комбинирование отдельных аргументов и rest

```javascript
function multiply(factor, ...numbers) {
  return numbers.map((num) => num * factor);
}

console.log(multiply(2, 1, 2, 3)); // [2, 4, 6]
```

---

### 🔹 2️⃣ Spread — Раскрытие массивов и объектов

**Идея:** С помощью Spread (`...`) вы можете:

- Копировать массивы или объекты.
- Слияние массивов или объектов.
- Передавать массивы в качестве отдельных аргументов.

---

#### 👇 Копия массива

Без `Spread`:

```javascript
const nums = [1, 2, 3];
const numsCopy = nums; // ССЫЛКА!

numsCopy.push(4);
console.log(nums); // [1, 2, 3, 4] — изменился исходный массив
```

Со `Spread`:

```javascript
const nums = [1, 2, 3];
const numsCopy = [...nums];
numsCopy.push(4);

console.log(nums); // [1, 2, 3]
console.log(numsCopy); // [1, 2, 3, 4]
```

---

#### 👇 Слияние массивов

```javascript
const arr1 = [1, 2];
const arr2 = [3, 4];
const combined = [...arr1, ...arr2];
console.log(combined); // [1, 2, 3, 4]
```

---

#### 👇 Копия и слияние объектов

```javascript
const user = { name: "Иван", age: 25 };
const userCopy = { ...user };
userCopy.name = "Мария";

console.log(user.name); // 'Иван' (не изменился!)
console.log(userCopy.name); // 'Мария'
```

---

#### 👇 Дополнение данных в объекте

```javascript
const user = { name: "Иван", age: 25 };
const updatedUser = { ...user, isAdmin: true };
console.log(updatedUser);
// { name: 'Иван', age: 25, isAdmin: true }
```

---

#### 👇 Передача массива в функцию

Без Spread:

```javascript
function sum(a, b, c) {
  return a + b + c;
}

const nums = [1, 2, 3];
sum(nums[0], nums[1], nums[2]); // 6
```

Со Spread:

```javascript
function sum(a, b, c) {
  return a + b + c;
}

const nums = [1, 2, 3];
sum(...nums); // 6
```

---

### 🔹 Итоговые различия

|                  | REST (`...args`)                            | SPREAD (`...array`)                             |
| ---------------- | ------------------------------------------- | ----------------------------------------------- |
| Смысл            | Сбор данных в массив                        | Раскрытие массива или объекта                   |
| Где используется | На позиции параметров в определении функции | При вызове функции или создании массива/объекта |
| Назначение       | Сбор оставшихся аргументов                  | Копирование, объединение данных                 |

---

### ✅ Дополнительно: Полезный короткий пример для закрепления

```javascript
function processData(a, b, ...other) {
  console.log(a, b, other);
}
processData(1, 2, 3, 4, 5);

// a = 1
// b = 2
// other = [3, 4, 5]
```

---

### ⚡️ Итоговые ключевые моменты

✅ **Rest** — используется в определении функций для сбора аргументов в массив.
✅ **Spread** — используется для раскрытия массива или объекта в новую структуру данных или в список аргументов.
✅ Копировать массивы и объекты нужно только с помощью `...` для создания новых, а не для создания ссылок.
✅ Передача данных в функциях становится удобнее и короче.

---

Таким образом, `...` в JavaScript — универсальный инструмент для манипуляции данными, который значительно упрощает чтение и поддержку кода.

## 🟠 7. Итерация и обработка данных

### ⚡️ Зачем нужны методы массива

С приходом ES5 и активным распространением ES6 обработка данных в массивах в JavaScript кардинально изменилась. Вместо того чтобы вручную писать громоздкие циклы `for`, сейчас используется удобный и короткий инструментарий:

- `forEach()` — перебрать массив
- `map()` — трансформировать массив
- `filter()` — выбрать элементы
- `reduce()` — собрать результат (сумму, объект и т. д.)
- `sort()` — сортировать данные

**Итог:** Код стал коротким, чистым и удобным для чтения.

---

### 🔹 1️⃣ `forEach()` — Перебор массива

Используется для выполнения определенного действия для каждого элемента массива.
**Не возвращает значение.**
Часто используется для логирования данных или изменения внешнего состояния.

#### 👇 Пример

```javascript
const nums = [1, 2, 3];
nums.forEach((num, index) => {
  console.log(`Элемент ${index}: ${num}`);
});
// Выведет:
// Элемент 0: 1
// Элемент 1: 2
// Элемент 2: 3
```

---

### 🔹 2️⃣ `map()` — Трансформация массива

Используется для создания **нового массива** из старого, применяя определенную логику для каждого элемента.

#### 👇 Умножение каждого элемента на 2

```javascript
const nums = [1, 2, 3];
const doubled = nums.map((num) => num * 2);
console.log(doubled); // [2, 4, 6]
```

#### 👇 Трансформация объектов

```javascript
const people = [
  { name: "Иван", age: 25 },
  { name: "Мария", age: 30 },
];
const names = people.map((person) => person.name);
console.log(names); // ["Иван", "Мария"]
```

---

### 🔹 3️⃣ `filter()` — Отбор данных

Используем для создания нового массива, в который попадут только элементы, удовлетворяющие условиям проверки.

#### 👇 Отбор четных элементов

```javascript
const nums = [1, 2, 3, 4, 5];
const even = nums.filter((num) => num % 2 === 0);
console.log(even); // [2, 4]
```

#### 👇 Отбор пользователей старше определенного возраста

```javascript
const users = [
  { name: "Иван", age: 25 },
  { name: "Мария", age: 17 },
  { name: "Петр", age: 31 },
];
const adults = users.filter((user) => user.age >= 18);
console.log(adults);
// [{name: 'Иван', age: 25}, {name: 'Петр', age: 31}]
```

---

### 🔹 4️⃣ `reduce()` — Свертка данных

Используем, когда нужно собрать все данные в одну финальную величину:

- Сумму
- Итоговую строку
- Сводный объект
- И т. д.

#### 👇 Сумма элементов массива

```javascript
const nums = [1, 2, 3, 4];
const total = nums.reduce((sum, num) => sum + num, 0);
console.log(total); // 10
```

#### 👇 Группировка данных

```javascript
const people = [
  { name: "Иван", age: 25 },
  { name: "Мария", age: 30 },
  { name: "Петр", age: 25 },
];
const grouped = people.reduce((acc, person) => {
  const { age } = person;
  if (!acc[age]) {
    acc[age] = [];
  }
  acc[age].push(person.name);
  return acc;
}, {});

console.log(grouped);
// {
//   "25": ["Иван", "Петр"],
//   "30": ["Мария"]
// }
```

---

### 🔹 5️⃣ `sort()` — Сортировка массива

Используем для упорядочивания элементов в массиве.
По умолчанию метод `sort()` сортирует **строки** в **лексикографическом** (алфавитном) порядке.
Для массива строк это удобно:

#### 👇 Сортировка строк

```javascript
const words = ["яблоко", "апельсин", "банан"];
const sortedWords = words.sort();
console.log(sortedWords);
// ["апельсин", "банан", "яблоко"]
```

✅ Здесь всё ясно — сортируем строки в алфавитном порядке.

---

#### ⚠️ Почему нужно передавать колбек для чисел?

Для массива чисел метод `sort()` **так же приводит элементы к строкам** и сортирует их как строки!
То есть:

```javascript
const nums = [10, 5, 100, 1];
const sortedNums = nums.sort();
console.log(sortedNums);
// [1, 10, 100, 5]
```

❌ **Результат не тот, что ожидается!**
«100» идёт раньше «5», потому что `'100' < '5'` в лексикографической сортировке.

---

#### 👇 Правильный способ — указать колбек-функцию для сортировки чисел:

```javascript
const nums = [10, 5, 100, 1];
const sortedNums = nums.sort((a, b) => a - b);
console.log(sortedNums);
// [1, 5, 10, 100]
```

✅ Теперь сортировка идёт в **числовом** порядке, потому что:

- Колбек принимает две пары элементов массива — `a` и `b`.
- Возврат:

  - **Отрицательное число** — `a` идёт раньше `b`.
  - **Положительное число** — `a` идёт позже `b`.
  - **0** — позиции не изменяются.

#### 👇 Сортировка в обратном порядке:

```javascript
const nums = [10, 5, 100, 1];
const sortedNums = nums.sort((a, b) => b - a);
console.log(sortedNums);
// [100, 10, 5, 1]
```

---

#### ⚡️ Ключевые особенности `sort()`:

- Сортировка происходит прямо в исходный массив (мутирует его).
- Для строк — сортировка идёт в лексикографической последовательности.
- Для чисел необходимо обязательно передавать колбек:

  - `a - b` — для сортировки **по возрастанию**.
  - `b - a` — для сортировки **по убыванию**.

---

#### 👇 Итоговые короткие примеры для запоминания:

```javascript
// Строки
["в", "а", "б"].sort(); // ["а", "б", "в"]

// Числа (без колбека — НЕПРАВИЛЬНЫЙ результат!)
[100, 5, 1].sort(); // [1, 100, 5]

// Числа (с колбеком — ПРАВИЛЬНЫЙ результат!)
[100, 5, 1].sort((a, b) => a - b); // [1, 5, 100]
```

---

### ⚡️ Итоговые различия

| Метод       | Назначение                               | Возврат результата?           |
| ----------- | ---------------------------------------- | ----------------------------- |
| `forEach()` | Перебор для выполнения действия          | ❌ нет                        |
| `map()`     | Трансформация элементов в новые значения | ✅ массив                     |
| `filter()`  | Отбор элементов по условию               | ✅ массив                     |
| `reduce()`  | Свертка массива в одно значение          | ✅ любое значение             |
| `sort()`    | Сортировка элементов массива             | ✅ тот же массив (изменяется) |

---

### ⚡️ Итоговые ключевые моменты

✅ `forEach()` — выполняет действие для каждого элемента.
✅ `map()` — изменяет каждый элемент, формируя новый массив.
✅ `filter()` — оставляет только нужные элементы массива.
✅ `reduce()` — приводит массив к единому результату.
✅ `sort()` — сортирует массив прямо в нем (работает с изменением оригинала).

---

### 👇 Короткий совмещенный example для понимания

```javascript
const nums = [5, 1, 4, 2, 3];
const result = nums
  .sort((a, b) => a - b) // [1, 2, 3, 4, 5]
  .filter((num) => num % 2 !== 0) // [1, 3, 5]
  .map((num) => num * 10) // [10, 30, 50]
  .reduce((sum, num) => sum + num, 0); // 10 + 30 + 50 = 90

console.log(result); // 90
```

## 🟠 8. Практика на массивах

### 🔹 1️⃣ Поиск данных в массиве

Частая задача — реализовать поиск данных в массиве. Допустим, есть список пользователей, и нужно найти всех, в чьих именах встречается введённый фрагмент текста.

#### 👇 Исходный массив

```javascript
const users = [
  { id: 1, name: "Иван" },
  { id: 2, name: "Мария" },
  { id: 3, name: "Петр" },
  { id: 4, name: "Иванна" },
];
```

#### 👇 Реализация поиска

Используем:

- `filter()` для проверки условия
- `includes()` для проверки вхождения текста в имя
- `toLowerCase()` для нечувствительной к регистру проверки

```javascript
function searchUsers(users, query) {
  return users.filter((user) =>
    user.name.toLowerCase().includes(query.toLowerCase())
  );
}

console.log(searchUsers(users, "иван"));
// Выведет:
// [
//   { id: 1, name: 'Иван' },
//   { id: 4, name: 'Иванна' }
// ]
```

💡 Так делается поиск пользователей в любом поисковом поле!

---

### 🔹 2️⃣ Сортировка массива

Частая практика — сортировать данные:

- По `id` (числовой ключ).
- По `name` (строка).
- По `date` (временная метка).

#### 👇 Сортировка по `id` (числовой ключ)

```javascript
const data = [
  { id: 3, name: "Петр" },
  { id: 1, name: "Иван" },
  { id: 2, name: "Мария" },
];
const sortedById = [...data].sort((a, b) => a.id - b.id);
console.log(sortedById);

// [{ id: 1, name: 'Иван' }, { id: 2, name: 'Мария' }, { id: 3, name: 'Петр' }]
```

---

#### 👇 Сортировка по `name` (строковые данные)

Для сортировки текста нужно использовать метод `localeCompare()` для правильной проверки в любом языке:

```javascript
const sortedByName = [...data].sort((a, b) =>
  a.name.localeCompare(b.name, "ru")
);
console.log(sortedByName);

// [{ id: 1, name: 'Иван' }, { id: 2, name: 'Мария' }, { id: 3, name: 'Петр' }]
```

---

#### 👇 Сортировка по `date`

Частый кейс — сортировка данных, приходящих в формате дат (`YYYY-MM-DD`):

```javascript
const events = [
  { id: 1, title: "Встреча", date: "2023-06-21" },
  { id: 2, title: "Совещание", date: "2023-06-19" },
  { id: 3, title: "Обед", date: "2023-06-20" },
];
const sortedByDate = [...events].sort(
  (a, b) => new Date(a.date) - new Date(b.date)
);
console.log(sortedByDate);

// [
//   { id: 2, title: 'Совещание', date: '2023-06-19' },
//   { id: 3, title: 'Обед', date: '2023-06-20' },
//   { id: 1, title: 'Встреча', date: '2023-06-21' }
// ]
```

---

### 🔹 3️⃣ Реализация пагинации

Иногда данных много, и нужно вывести их **частями** (например, 5 элементов на страницу). Эта практика отлично дополняет поиск и сортировку.

---

#### 👇 Наш массив данных для примера

```javascript
const products = [
  { id: 1, title: "Телефон" },
  { id: 2, title: "Ноутбук" },
  { id: 3, title: "Планшет" },
  { id: 4, title: "Часы" },
  { id: 5, title: "Наушники" },
  { id: 6, title: "Клавиатура" },
  { id: 7, title: "Мышь" },
  { id: 8, title: "Монитор" },
  { id: 9, title: "Принтер" },
  { id: 10, title: "Сканер" },
];
```

---

#### 👇 Функция для создания страницы

```javascript
function paginate(data, page = 1, perPage = 3) {
  const totalItems = data.length;
  const totalPages = Math.ceil(totalItems / perPage);
  const start = (page - 1) * perPage;
  const end = start + perPage;

  const pageItems = data.slice(start, end);
  return {
    page,
    perPage,
    totalPages,
    totalItems,
    items: pageItems,
  };
}
```

---

#### 👇 Тестируем пагинацию

```javascript
// Допустим, нужно вывести 1‑ю страницу
const page1 = paginate(products, 1, 3);
console.log(page1);
/*
{
  page: 1,
  perPage: 3,
  totalPages: 4,
  totalItems: 10,
  items: [
    { id: 1, title: 'Телефон' },
    { id: 2, title: 'Ноутбук' },
    { id: 3, title: 'Планшет' }
  ]
}
*/

// Допустим, нужно вывести 3‑ю страницу
const page3 = paginate(products, 3, 3);
console.log(page3);
/*
{
  page: 3,
  perPage: 3,
  totalPages: 4,
  totalItems: 10,
  items: [
    { id: 7, title: 'Мышь' },
    { id: 8, title: 'Монитор' },
    { id: 9, title: 'Принтер' }
  ]
}
*/
```

---

### ✅ Ключевые нюансы реализации

✅ `slice()` — удобный метод для извлечения части массива.
✅ Текущая страница (`page`) определяет стартовый индекс.
✅ Количество элементов на странице (`perPage`) определяет длину фрагмента массива.
✅ Дополнительно считаем количество страниц для удобства создания кнопок в будущем.

---

### ⚡️ Итоговые ключевые моменты

1. Научились искать данные в массиве с помощью `filter()` и `includes()`.
2. Научились сортировать данные (`sort()`): по `id`, `name` и `date`.
3. Научились реализовывать **пагинацию** — делить большой массив данных на удобные части для отображения.

| Задача               | Метод                     | Ключевые детали                                                             |
| -------------------- | ------------------------- | --------------------------------------------------------------------------- |
| Поиск текста         | `filter()` + `includes()` | Учитываем регистры (`toLowerCase()`), проверяем вхождение текста.           |
| Сортировка по `id`   | `sort()`                  | Числовой ключ: `a.id - b.id`.                                               |
| Сортировка по `name` | `sort()`                  | Текстовые данные — используем `localeCompare()` для правильного результата. |
| Сортировка по `date` | `sort()`                  | С датами работаем как с объектами `Date`: `new Date(a.date)`.               |
| Пагинация            | `slice()`                 | Деление большого массива данных на удобные части для отображения.           |

## 🟠 9. Запросы к серверу

### ⚡️ Что такое запросы к серверу простыми словами

Запрос к серверу — это как письмо или просьба:

1. Ты (браузер) отправляешь **запрос** (например, «дай список пользователей»).
2. Сервер принимает его, выполняет обработку и отправляет **ответ** (например, список пользователей).
3. Ты получаешь результат и делаешь что-то с ним (например, отображаешь список пользователей в интерфейсе).

#### 👇 Схема обмена данных

```
[Браузер (frontend)] ----(запрос)----> [Сервер (backend)]
        |                                 |
        <--(ответ: данные / статус)-----
```

Чаще всего обмен идёт в формате JSON — удобный для чтения как для программ, так и для людей.

---

### ⚡️ Общая идея

Современный JavaScript имеет несколько способов сделать запрос к серверу.
Для каждого рассмотрим короткий и понятный код, обращаемся к популярным **API с фейковыми данными**:

| Метод          | Сайт для данных                                                                          |
| -------------- | ---------------------------------------------------------------------------------------- |
| XMLHttpRequest | [https://jsonplaceholder.typicode.com/posts](https://jsonplaceholder.typicode.com/posts) |
| Fetch API      | [https://fakestoreapi.com/products](https://fakestoreapi.com/products)                   |
| async/await    | [https://jsonplaceholder.typicode.com/users](https://jsonplaceholder.typicode.com/users) |
| Axios          | [https://reqres.in/api/users](https://reqres.in/api/users)                               |

---

### 🔹 1️⃣ `XMLHttpRequest` — устаревший способ

Используем для обращения к серверу. Код более громоздкий, но позволяет понять сам принцип AJAX.

#### 👇 Пример: Получение списка постов

```javascript
const xhr = new XMLHttpRequest();
xhr.open("GET", "https://jsonplaceholder.typicode.com/posts", true);
xhr.onload = function () {
  if (xhr.status === 200) {
    const posts = JSON.parse(xhr.responseText);
    console.log("XMLHttpRequest — Посты:", posts.slice(0, 3)); // первые 3 записи
  } else {
    console.error("Ошибка запроса!");
  }
};
xhr.send();
```

---

### 🔹 2️⃣ `Fetch API` — современный стандарт

Используем для создания удобной цепочки `.then()` для обработки данных.

#### 👇 Пример: Получение списка товаров

```javascript
fetch("https://fakestoreapi.com/products")
  .then((response) => response.json()) // <-- Метод .json()
  .then((data) => {
    console.log("Fetch API — Товары:", data.slice(0, 3));
  })
  .catch((error) => {
    console.error("Ошибка запроса!", error);
  });
```

#### ⚡️ Что делает метод `.json()`?

`response.json()` — это метод, который читает тело ответа в формате JSON и превращает его в JavaScript-объект.
По сути, это удобный эквивалент того же, что делаем вручную:

```javascript
const data = JSON.parse(responseText);
```

Таким образом:

- `response.json()` — удобный и короткий метод для `JSON.parse`.
- Синтаксис примерно тот же, что и в методе `JSON.parse`, но сам метод является **асинхронным** и возвращает `Promise`.

---

### 🔹 3️⃣ `async/await` — удобный для чтения стиль

Используем для того, чтобы код выглядел линейным, хотя он выполняется асинхронно.

#### 👇 Пример: Получение пользователей

```javascript
async function loadUsers() {
  try {
    const response = await fetch("https://jsonplaceholder.typicode.com/users");
    const users = await response.json();
    console.log("async/await — Пользователи:", users.slice(0, 3));
  } catch (error) {
    console.error("Ошибка запроса!", error);
  }
}
loadUsers();
```

#### ⚡️ Почему это удобно?

- `async` — говорит JavaScript, что в этой функции есть асинхронный код.
- `await` — говорит: «жди результата» для промиса.

Таким образом:

- Код выполняется в удобной для чтения последовательности, как будто он синхронный.
- На самом деле он не блокирует весь поток, а просто удобно делегирует выполнение асинхронной операции.

#### 👇 Схема для понимания

```
loadUsers()
  --> выполняется
    --> отправляется fetch-запрос
    <-- приходят данные
    --> данные приводим в формат JSON
    --> результат доступен для дальнейших действий
```

---

### 🔹 4️⃣ `Axios` — популярная библиотека

`Axios` — удобный инструмент для отправки запросов, особенно в крупных приложениях.
Чаще используется в связке с фреймворками, такими как **React**, **Vue**, **Angular**.
Для чистого JavaScript — не обязателен.

✅ Установка (через npm):

```
npm install axios
```

#### 👇 Подключение в коде

```javascript
import axios from "axios";

async function loadData() {
  try {
    const response = await axios.get("https://reqres.in/api/users?page=2");
    console.log("Axios — Пользователи:", response.data.data);
  } catch (error) {
    console.error(error);
  }
}

loadData();
```

`axios` стоит рассматривать в связке с фреймворками (например, React). Для начала понимания AJAX-запросов достаточно:

- `fetch()` — для современных приложений,
- `async/await` — для удобства чтения.

---

### ⚡️ Итоговые ключевые различия

| Метод            | Уровень сложности | Краткая характеристика                       |
| ---------------- | ----------------- | -------------------------------------------- |
| `XMLHttpRequest` | Высокий           | Устаревший, много кода, низкий уровень       |
| `fetch()`        | Средний           | Простота записи, удобный промисный стиль     |
| `async/await`    | Средний           | Идеальный для современных приложений         |
| `axios`          | Средний           | Дополнительно ставится, удобный для REST API |

---

### ⚡️ Дополнительно: памятка для GET и POST

#### 🔹 GET-запрос

Используем, когда нужно только **получить данные**.
👉 Метод не указывается, это значение **по умолчанию**.

```javascript
// С fetch
fetch("https://example.com/api/data")
  .then((response) => response.json())
  .then((data) => {
    console.log(data);
  });

// С async/await
async function loadData() {
  const response = await fetch("https://example.com/api/data");
  const data = await response.json();
  console.log(data);
}
loadData();
```

---

#### 🔹 POST-запрос

Используем для **отправки данных**.
👉 Нужно указать:

- Метод: `'POST'`
- Заголовки (`headers`) — тип данных (чаще `'Content-Type': 'application/json'`)
- Тело (`body`) — данные в формате JSON

```javascript
// С fetch
fetch("https://example.com/api/data", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
  },
  body: JSON.stringify({ name: "Иван", age: 25 }),
})
  .then((response) => response.json())
  .then((data) => {
    console.log(data);
  });

// С async/await
async function sendData() {
  const response = await fetch("https://example.com/api/data", {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
    },
    body: JSON.stringify({ name: "Иван", age: 25 }),
  });
  const result = await response.json();
  console.log(result);
}
sendData();
```

---

### ⚡️ Итог

✅ Для `GET` — метод не указываем (это дефолтный).
✅ Для `POST` — обязательно указать метод, заголовки и тело запроса.
✅ Синтаксис для `fetch()` и для `async/await` одинаковый — различается лишь способом записи результата.

### ✅ Вывод

Все рассмотренные способы дают одинаковый результат — получение данных с API.
Для современных приложений оптимальный старт — `fetch()` и `async/await`.
`XMLHttpRequest` полезен для понимания истории и принципов, а `axios` стоит оставить для случаев, когда вы будете работать с большим проектом или фреймворком.
